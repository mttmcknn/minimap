# Follow-up hardening — 2026-09-16

This pass closes concrete gaps in quiet recovery, truthful destination checks,
and shared graph maintenance. The code and evaluations are local, uncommitted
development work. They do not establish universal self-healing or measured
model-token savings. See the [machine-readable results](2026-09-16-ethos.json)
and [runnable evaluations](../README.md).

## Gaps addressed

- A recovery budget previously depended on the host manually carrying limits between commands; a private recovery token now retains the original goal, checks, failed edges, remaining inputs, and deadline, and debits inputs before sending them.
- A recognized screen type could be mistaken for completion of a particular item/account task; repeatable `go --expect` anchors now require unique visible matches on a fresh destination, including an already-at-target request.
- Supersession deleted a route another supported app build could still use; a verified replacement now receives planning preference while the original route remains a fallback.
- A malformed later action could be discovered after earlier inputs had run; the complete graph's recipes are validated before input, with strict action payloads and backward-compatible selector aliases.
- Post-action learning could record an unsettled frame; it now requires matching usable observations, while replay waits for its known destination and goal checks within bounded attempts and deadlines.
- Empty/null-root accessibility captures lacked a bounded retry path; full observations now retry those specific transient failures, without accepting malformed or partial output as a destination.
- Editable/password content and private action metadata could enter memory; explicit private-input content is redacted before caching/fingerprinting, and obvious sensitive labels, intents, and selectors are rejected before input.
- Relearning a route after renaming a place could create duplicate edge files; both the edge ID prefix and digest now depend on immutable place IDs and the complete recipe.
- Team graph health checks now detect duplicate identities and invalid recipes/privacy metadata; real Git evaluations cover disjoint additions and conflicting edits.

The canonical skill is version 2.2 and is the source embedded by `minimap init`.
It tells hosts to propagate `--recovery` through every command for an unresolved
goal, retain its original expectations, verify source-supported repairs, and
keep ordinary recovery inside the agent workflow. A host can still bypass a
budget by incorrectly starting a new goal; the token is a workflow contract,
not a security boundary against a hostile agent.

New lean edge records use `minimap.edge.v2`. Existing lean v1 edge records load
without rewriting the checkout. Older clients reject the new schema rather
than ignoring fallback semantics, so teams must upgrade their CLI and copied
skills together. This does not migrate the older 0.1.x product graph format.

## Emulator and team outcomes

APKs came from the same pinned Compose samples build used in the first report.
Android CLI installed/launched fixtures and supplied independent layout checks;
Minimap performed learned navigation and repair replay. All work targeted the
two named emulators. Existing sample checkouts and their graphs were preserved.

| Case | Result |
| --- | --- |
| Renamed Search control, API 36 and 37 | Both stale routes failed without changing the graph; both scripted repairs replayed successfully from a teammate graph copy. |
| Repaired graph on the older APK | Both renamed-control cases recovered through the retained original route when the new selector disappeared. |
| Search moved behind Profile, API 36 and 37 | Both repairs learned Home → Profile → Search and replayed on the new and older APKs; the replacement route itself also worked on the older APK. |
| Wrong Search callback opens Cart | Two reproductions on each API returned unresolved statuses (`unknown`, then `needs_label`), with independent Cart evidence and no shared-graph mutation. |

| Jetchat on API 37 | Three of three profile/conversation round trips passed; all three wrong-person checks returned `goal_mismatch` without graph mutation. |
| External navigation on API 36 | `go home` observed the actual Search starting state and returned to Home without false success. |
| Real Git merges | Four independently learned graph additions merged and passed read-only `doctor`; contradictory edits to one place produced a Git conflict and failed `doctor` without rewriting evidence. |
| Rename and relearn on API 36 | The final regression trial passed: the place ID and two edge IDs were preserved, exit labels updated, and a fresh graph copy reached the renamed destination. |

The repaired graph trials include an older-APK check that was absent from the
first pass. Their total Minimap subprocess times were 71.29/77.65 seconds for
rename/relocation on API 37 and 75.53/84.46 seconds on API 36. Each scenario used
eight Minimap commands, including teammate and older-build replay. Host budget
readings at the last command were 104.48/108.25 seconds on API 37 and
111.48/118.00 on API 36, below the shared 180-second limit; those readings exclude
the final independent oracle. The conservative host action counts were 7/10,
below 32. Engine tokens also persisted across each unresolved goal.

These are scripted host workflows with known fixture changes. Zero interactive
decisions in those scripts does not prove an arbitrary agent will diagnose an
unseen change or notify the user correctly. The fixture's matching source
corroborates the deliberately wrong callback; the binary does not analyze code.

## Timing and output

The API 36 comparison rotated five trials per arm. Every trial passed the same
independent Search oracle. Raw navigation used layout → tap → layout. Minimap
used one `go` with three required Search anchors, so a separate full-layout
response was unnecessary. This differs from the earlier `go` → `layout` mode.

| Arm | Success | Median seconds | Top-level commands | Response bytes |
| --- | ---: | ---: | ---: | ---: |
| Raw Android | 5/5 | 6.810 | 3 | 6,017 |
| Cold Minimap | 5/5 | 7.469 | 1 | 804 |
| Warm Minimap | 5/5 | 7.854 | 1 | 804 |

Minimap returned **86.6% fewer bytes** and used two fewer top-level commands.
It was **0.66–1.04 seconds slower** on this one-hop route. Neither warm caches
nor output reduction are treated as permission to skip a fresh source check.
These timings exclude deployment, fixture reset, warm-up, and the extra
independent oracle. They do not measure model reasoning or billed tokens.

Learning both Jetsnack directions took 27.16 seconds and four commands.
JetNews/Jetchat learning took 44.76/44.96 seconds and six commands; median round
trips were 22.80/22.80 seconds, two `go` commands and four actions each. Learning
now pays for stable destination observations. There was no paired raw drawer
benchmark, and no wall-time break-even was demonstrated by the one-hop trial.

## Verification and retained failures

The final Rust suite passes **146 tests**, covering budget persistence and
pre-input debit, preserved original goal checks, malformed later actions,
private content, fallback routes, v1 edge reads, observation settling, recipe
identity after relabeling, and the earlier hardening regressions. Formatting,
Clippy with warnings denied, the release build, and canonical skill validation
pass. A harness timeout probe also verifies that elapsed time and partial output
are retained when its subprocess watchdog fires.

The relabel regression failed before the fix with identical recipe hashes but
different filename prefixes (`home_profile` versus `home_account`). Current
labels were already corrected during graph loading; the problem was duplicate
route IDs, not stale label lookup. An initially sparse test fixture was rejected
by conservative matching and was corrected to retain shared page content.
A full-suite run also exposed a test assumption that an expired preflight must
have started a subprocess; the fixture now initializes an empty trace so that
zero attempted inputs are represented correctly. The final rerun passed.

Earlier API 37 null-root failures remain in the
[first report](2026-09-16-self-healing.md). This pass obtained seven usable raw
install/layout probes and completed the recovery and drawer evaluations on
API 37. The prior failure's root cause is still unproven. Scripted tests prove
bounded transient retries; successful live runs do not establish a cure for
every accessibility-service failure.

The first API 37 recovery run inherited an incorrect `goal_checks: false`
metadata default, although its saved `go` commands include both goal anchors.
The harness now records that mode correctly; the original trace is preserved.
Later harness improvements also record timeout failures and the final oracle in
scenario elapsed time. Earlier measurements are labeled according to what they
actually captured rather than rewritten as newer measurements.

## Provenance and remaining gates

The base Minimap revision is `e838065b7b9f837f11233e452afc47e8bbdeefb0`, with
uncommitted changes. Compose samples are pinned to
`d3ff757b289f7036815978a8f7b16706ee3423b0`. APK hashes, binary hashes, run summaries,
and retained artifact locations are in the JSON report. The host is macOS arm64
with Rust 1.98.1, JDK 21, Android CLI 1.0.15498356, and adb 37.0.1. Emulators use
API 36 at 1080×2400 and API 37 at 1080×2424.

Three binary revisions are distinguished: the initial recovery/timing build;
the build with the updated skill/help used for API 36 recovery and API 37
drawers; and the final build with stable edge prefixes used for relabeling.
The complete Rust suite runs against the final source. The installed Homebrew
binary was not replaced, and this work has not been published or merged.

Remaining evidence and product boundaries:

- Actual model tokens, billed cost, and end-to-end task break-even remain unmeasured; independent agent trials must include discovery, source inspection, failed recovery, and graph maintenance.
- Locale/font/foldable and broader app-state coverage, held-out matching data, and sustained accessibility failure tests remain release gates; this sample does not establish p95 latency or a reliability SLA.
- Route preference preserves alternatives but does not model every feature flag, account, permission, or arrival-history precondition; Back recipes remain excluded from planning.
- Goal anchors prove visible evidence supplied by the host, not hidden business state; source confirmation remains an explicit agent assertion.
- Explicit private inputs and obvious sensitive metadata are protected, but unmarked personal text cannot be identified reliably from arbitrary UI.
- Disjoint Git additions were validated; conflicting semantic edits still require an agent to reconcile current UI/source evidence, and graph writes are atomic per file rather than a multi-file transaction.
