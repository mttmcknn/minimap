# Jetsnack baseline — 2026-09-16

The existing test suite is green, and ordinary navigation succeeds in this
small live smoke, but external navigation produces a false success. Fix source
verification and invalidation before treating cached replay as trustworthy.

## Ordinary navigation: Home → Search

The raw arm runs Android CLI layout → adb tap → Android CLI layout. The
Minimap arms run `go search` → `layout`, so both include the normal final
product-verification read. An additional fresh Android CLI layout checks the
actual destination outside the reported trial timing in every arm.

| Arm | Success | Median time | Median top-level commands | Median stdout bytes |
| --- | ---: | ---: | ---: | ---: |
| Raw Android | 5/5 | 5.669 s | 3 | 6,017 |
| Cold Minimap | 5/5 | 5.750 s | 2 | 5,208 |
| Warm Minimap | 5/5 | 2.942 s | 2 | 5,209 |

All ten Minimap replay graphs remained byte-for-byte unchanged. Cold trials
reported `start_source: layout`; warm trials reported `start_source: session`.

Warm replay is about 48% faster in this small sample, but the median becomes
5.753 s when the preceding source observation is included. It is a useful
optimization when that observation is already available, not free work to
omit from the economics. Cold timing is approximately the same as raw.
Including final layout verification reduces stdout bytes by about 13%, much
less than a comparison of navigation summaries alone.

Learning Home, Search, and both directional transitions used four Minimap
commands, 14.315 s, and 3,108 stdout bytes. This includes initialization and
labeling, but excludes deployment, fixture setup, and any agent reasoning.
It is not a measured token break-even point.

## Adversarial case: navigation outside Minimap

1. Independently establish Home and run `whereami` to populate a fresh session.
2. Use current Android CLI layout evidence and adb input to move to Search.
3. Independently confirm Search with a new Android CLI layout.
4. Ask Minimap to `go home`.
5. Independently inspect the real device again.

Minimap returned `status: ok` and `planned_path: []` in 0.054 s while the app
remained on Search. The runner correctly exits **1** for this false success.
The test leaves the emulator back on Home after collecting the evidence.
The bug is recorded here and remains unfixed in this planning pass.

## Checks and limits

The pre-existing 107 Rust/CLI tests, formatting, Clippy with warnings denied,
and the release build passed. They do not cover the live stale-session failure.

This is one route, one existing APK, one emulator, and five repeats per arm.
It does not establish p95 latency, cross-device/team reliability, matcher
accuracy on held-out apps, or agent token/cost savings. Deployment, fixture
setup, warmup, and independent-oracle calls are recorded separately. Timing
is the sum of top-level subprocess durations and does not include model
thinking or instrument nested Android/ADB calls. Token usage is explicitly
`null` in the data.

Raw command traces, stdout/stderr, and isolated graphs are retained outside
the repo at `/private/tmp/minimap-hardening-20260916/live-baseline`; only
the metric summary and this report are candidates for committing.
